# Проверка изменений

В репозитории один `Dockerfile` и один `compose.yaml`. `uv` запускается внутри
образа; серверные команды `watch.sh` используют Docker и Compose. Короткий `.env`
содержит `APP_ENV=production`, четыре секрета и только требуемые отличия от
`Settings`. При `VISION_ENABLED=false` vision-сервис не запускается.

## Автоматические проверки

На Windows выполнены Ruff, Django `check`, проверка миграций, Python unit,
functional, regression, architecture и integration (локальные зависимости),
Node (3 теста) и Chromium E2E (5 тестов с задержанным API). Python: 98 прошло,
3 теста внешних сервисов пропущены. Профили Compose `ops`, `tests`, `gpu`, `cpu` проходят
`docker compose config --quiet`; синтаксис Bash и JS проверен.

Локальный Docker daemon отсутствует, поэтому сборка `ops` и тестового образа,
а также PostgreSQL/RabbitMQ-контейнеры должны быть подтверждены на сервере.
В предыдущем серверном прогоне было пять падений: потоковый тест использовал
закрытую тестовую транзакцию, три E2E запускали формы до привязки JS-обработчиков,
архивный тест собирал исходники из неполного тестового образа. Эти причины
исправлены; новый серверный прогон требуется после публикации владельцем.

```bash
cd /home/main/projects/watch-service
git pull --ff-only origin main
bash scripts/watch.sh preflight
bash scripts/watch.sh test-containers
bash scripts/watch.sh deploy
bash scripts/watch.sh status
curl -fsS http://127.0.0.1:8086/health/live
```

`deploy` повторяет контейнерные тесты до миграций. Если тесты падают, рабочие
контейнеры не пересоздаются. При включении GPU отдельно выполнить
`bash scripts/watch.sh model`, задать `VISION_ENABLED=true` и
`VISION_DEVICE=0`, затем повторить `deploy`.

## Ручная приёмка

1. Через HTTPS proxy либо SSH-туннель на `localhost:8086` в Chrome/Firefox
   открыть `/login/`, войти администратором, увидеть тёмный кабинет по
   `renders/img.png`, меню, карточки камер, статистику и таблицу нарушений.
2. Добавить камеру, сохранить её параметры и контрольную линию, обновить
   страницу: значения сохраняются. Без vision камера остаётся offline, без
   ложной метки LIVE. Неавторизованному пользователю недоступны media и stream.
3. В мониторинге добавить камеры, изменить порядок и сетку; после перезагрузки
   раскладка остаётся. Проверить кнопки полноэкранного режима и offline-кадр.
4. Создать недельный интервал, настроить срок хранения, сформировать CSV и PDF,
   скачать файлы, затем выйти из кабинета.
5. На странице уведомлений создать, изменить и удалить получателя. При
   выключенном серверном флаге тестовая внешняя отправка остаётся недоступной.
6. После включения vision на реальных RTSP и GPU проверить кадры, направление
   пересечения, расписание, JPEG-доказательства, PDF, уведомления и логи.
   Эти проверки зависят от оборудования и внешних сервисов.n
